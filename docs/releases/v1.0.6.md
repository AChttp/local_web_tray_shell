# Switch v1.0.6

Stability release focused on two freeze fixes and a new session logging system.

## Highlights

- Application logging for troubleshooting: every session writes to its own file under `%LocalAppData%\SwitchShell\logs`, with each line flushed to disk as written — so even if the app hard-freezes or is killed, everything up to that moment survives. Logged events cover startup, WebView2 initialization, command start/exit/retry cycles (PIDs, exit codes, retry attempt and delay), restarts, taskkill results, site navigation failures, site health transitions, tray menu open/close, hide/restore from tray, config events, the exit path, and any unhandled exception with a full stack trace. A "打开日志文件夹" tray menu item opens the folder directly.
- Fixed the intermittent tray right-click menu freeze (menu items unclickable, clicking elsewhere did nothing, the whole desktop felt sluggish, Switch at 0% CPU). Root cause: while the tray menu's modal loop was running, the UI thread kept reading the startup registry key every second and pushing tray-tooltip updates into Explorer on every running-count change — a cross-process deadlock when Explorer's taskbar thread was blocked on our menu callback. The registry value is now cached, tooltip writes are skipped while the menu is open (and when unchanged), and both refresh timers pause while the menu is up.
- Fixed a whole-window freeze that appeared as "clicked a site, page loading, everything stopped responding". An integer overflow in the auto-retry backoff (`initialDelay * 2^(attempt-1)` cast to `int` before clamping) wrapped negative around attempt 31, turning auto-retry into a 0-second restart storm that flooded the UI message queue. The backoff now clamps before the cast and floors at 1 second, so retries cap at the configured max delay forever. This bug was found by reading the new session log, which showed 13,257 zero-delay retries in one session.
